# mon2api：产品主张与本地演示

## 一句话

mon2api 让开发者先为一个 AI 资源锁定预算，再用统一 API 调用；每笔用量进入账本，费用在预算内结算给提供者，未用预算可由消费者取回。

- **买方**：需要控制调用支出并核对每笔费用的开发者。会话固定一个资源、一个提供者、一份价格快照和预算，不承诺跨资源自动调度。
- **卖方**：运营符合接口要求的上游网关、希望按已结算用量收款的资源提供者。凭证刷新、资源健康与执行隔离由提供者自己的网关负责。
- **平台**：负责会话、预算预留、账单和结算；平台服务费为累计消费的 5%。结算交易能核对资金流，不能独立证明模型执行或上游报告的 Token 用量。

演示使用**隔离的本地 chain 31337 和无价值的 dUSD 测试代币**。预算锁定、结算和提现是真实的本地 EVM 交易；种子资源的模型输出及用量为**模拟**。Monad 测试网新版托管合约已独立完成链上开通、结算、退款和提现验证；Web 与 worker 现已默认读取测试网配置，浏览器钱包与真实网关的完整流程仍待验收。各项验证状态见 [开发任务](./TASKS.md)。

默认配置已切换至 Monad 测试网。下列本地演示与验收记录保留用于隔离测试，不代表当前运行网络；重现时必须显式设置 `MON2API_MODE=local`、`ALLOW_DEMO=true`，并使用独立数据库与数据目录。当前用户控制台仅提供真实钱包登录与网关资源，本地演示角色步骤不适用于当前界面。

## 五分钟演示卡

这份演示卡以桌面浏览器为主要展示入口，适用于产品展示和面试项目讲解，不代表已经报名任何赛事。公开讲述时只引用已经完成的验证；若参加特定比赛，另按官方页面核对截止日期、赛道与提交要求。

准备：打开正在运行的 `http://localhost:3000`。本次展示环境使用干净的隔离数据库 `mon2api_presentation_20261017` 和数据目录 `.runtime/presentation-20261017`；该目录的新合约支持会话 ID 消费者绑定。此前端到端测试的 `mon2api_showcase_20261017` 与 `.runtime/showcase-20261017` 也已保留，原数据库与 `.runtime/ganache` 均未修改。不要在旧合约上创建新预算会话。今后从空环境准备时按 [README 的本地启动步骤](../README.md#本地启动)运行 `pnpm install`、`pnpm setup`、`pnpm dev`，并显式设置 `MON2API_MODE=local`、`ALLOW_DEMO=true`，为新演示配置独立的 `DATABASE_URL` 与 `MON2API_DATA_DIR`。让开发服务保持运行。准备一个已上架的「模拟模型」资源；种子资源如曾被提供者下架，需要先恢复上架。演示账户仅在本地链开放。

## 可重复的机器核验

需要重复机器核验时，请先使用独立的验证数据库和链数据目录启动服务，再在另一终端执行：

```bash
pnpm test:e2e
```

脚本会创建会话和资金交易。当前干净的现场展示账本不要再运行该脚本；已完成的验证账本保留在 `mon2api_showcase_20261017` 与 `.runtime/showcase-20261017`。

该脚本只连接本地 Web 与 chain 31337。它需要已上架的「Northstar Pool」演示资源；如果该资源曾被下架，请先在「我的号池」恢复上架。脚本用官方 OpenAI SDK 调用普通和流式接口，核对模拟响应、`demo` 用量、两笔账单、重复请求拒绝、结算、退款、Key 撤销和提供者提现。自动结算可能在手动调用前完成，也可能将两笔账单分成不同批次；应以**已确认交易的金额合计、账单状态及无重复结算**为验收条件。脚本会保留审计账单。2026-10-17，仓库的 `pnpm verify` 通过格式、lint、类型检查、309 项测试和生产构建；隔离的新合约环境中，`pnpm test:e2e` 的 8 项检查全部通过。此前两项隔离恢复场景已通过，但这次没有重跑；广播后、确认前的交易恢复窗口仍待专项修复。这些本地检查不构成真实上游或测试网 Web 交易的验证。

在关闭会话之前，开发者还可以在「API 密钥」创建仅绑定该会话的 Key，再按 [README 的 API 示例](../README.md#api-调用)发送请求。每次新请求都使用新的 `Idempotency-Key`；重复同一键应返回 409，且不增加账单。不要在公开演示画面展示完整 Key。

## 评审表达与产品验证

**60 秒讲述稿：**「开发者向小型 AI 资源提供者买调用量时，常担心价格变化、预算失控和账单无法核对。mon2api 先为一个资源锁定预算和价格，再按请求预留额度、记录用量、链上结算给提供者。今天展示本地测试链上的资金闭环：一次模拟模型调用的账单、已确认结算交易、消费者取回未用预算和提供者提现。模型输出与用量是模拟的；Monad 测试网新版合约已独立验证资金路径，真实网关和测试网 Web 交易还需验收。」

推荐按「痛点 → 一次预算会话 → 账单与链上交易 → 买卖双方取回资金 → 能力边界」讲述。评审可以在界面看到同一笔调用的费用，在交易中核对结算，再分别核对消费者退款与提供者收入。这是**可演示的本地资金闭环**。测试网新版合约的资金操作已独立验证；它仍没有测试网 Web/数据库/浏览器钱包的完整路径，也不能证明模型执行。

**区别讲准：**成熟路由产品已支持提供者选择和价格上限，例如 [OpenRouter 的提供者路由文档](https://openrouter.ai/docs/guides/routing/provider-selection)中的 `max_price` 是模型输入/输出单价上限。mon2api 当前的重点是**一笔预算会话的预付托管、固定价格快照、用量账本和提供者分账**。不要宣称“首创模型路由”“完全免信任计量”或“Monad 测试网 Web 服务已上线”。链上合约限制累计结算和退出规则；用量仍由上游报告、平台核对。

下一步按证据推进，不以页面数量衡量进度：

1. **首次使用**：请 3 位未看过项目的开发者按本页完成首次调用，记录能否在 5 分钟内找到账单、结算交易和未用预算；修掉他们重复遇到的阻塞。
2. **真实供给**：取得一个获授权的上游网关后，以 `upstream_reported` 跑一次带最终 usage 与上游请求 ID 的调用，并核对账单和提供者收入；模拟数据不计入真实成功率。
3. **外部资金路径**：新版合约已由 viem 测试钱包在 Monad 测试网完成锁预算、结算、关闭与双方提现，公开交易证据见下文；接下来用浏览器钱包连接 Web/数据库和获授权网关，记录同一会话的交易费与确认时间。测试代币不代表可兑付资产。
4. **异常解释**：现场展示重复请求不重复扣款、缺失用量保留预留待核对、重启后结算可恢复。相关约束与尚未完成的验证见 [开发任务](./TASKS.md)和[连接器文档](./POOL.md)。

项目展示或求职案例可以围绕明确的工程证据组织：预算不能超支、价格快照固定、异常用量进入核对、持久化结算任务按链上事件恢复。每项都附测试命令或交易链接，并标注本地验证与外部验证的区别。新版合约要求会话 ID 前 20 字节属于开通钱包；有资金且已授权的其他钱包抢占同一 ID 时会被拒绝，本地合约测试与隔离端到端检查已通过。旧合约没有该规则，服务端拒绝在旧部署新开会话；旧账本继续用于已有会话的结算、关闭与提现。合约不能原地升级，新旧部署应保持独立数据库和数据目录。广播后、确认前的结算交易恢复仍有未覆盖窗口，不能称为完整故障恢复。
