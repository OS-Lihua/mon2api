# Token2API：产品主张与验证

Token2API 让开发者先为一个 AI 资源锁定预算，再用统一 API 调用。用量进入账本，费用在预算内结算给提供者，未用预算可由消费者取回。

- 买方选择资源、结算链和资产对应的部署。会话固定资源、提供者、价格与预算。
- 卖方按该部署的资产报价，运营上游网关，并提取已结算收入。
- 平台预留预算、核对用量并累计结算。默认服务费为累计消费的 5%；链上记录不能独立证明模型执行质量。

支持的链、稳定币合约选择与部署边界见[多链结算](./MULTICHAIN.md)。各实例固定一条链和一种资产，不自动换币或跨链。

## 本地可重复验证

先准备本地 PostgreSQL。以下脚本为每次执行创建独立 schema 和临时回环链 31337，结束后清理测试 schema，不使用已有业务账本或远程 RPC。

```bash
pnpm verify
pnpm test:native
pnpm test:stable
pnpm test:stable --18-decimals
```

资金测试使用本地 ETH 和自建 ERC20 测试合约。ERC20 的 6 位、18 位精度分别验证，测试合约不代表真实 USDC 或 USDT。每条资金路径覆盖：

1. 锁定预算、确认会话，只返回一次初始 Key。
2. 通过 REST Key 调用模拟文本模型，记录费用并拒绝重复请求。
3. 用量不确定时保留 REVIEW 预留，核对前不能释放该部分预算。
4. 完成累计结算、平台分账、退款、双方提现，核对合约资金守恒。
5. 模拟链上成功但数据库确认丢失，恢复同一结算回执且不重复入账。

当前界面只展示真实钱包登录与网关资源。测试脚本中的演示角色和模拟模型不等于浏览器验收。

## 各链验收

为每条目标链、每个稳定币合约准备独立账本。使用两个真实钱包与获授权网关，串起同一会话的登录、授权、锁预算、模型请求、账单、结算、关闭、退款和提现。记录合约、回执、确认深度与费用。

本地回归通过不等于各主网已部署或审计。浏览器扩展钱包、移动钱包、真实稳定币版本和真实上游需在目标环境独立验收。任何公开演示均不得展示完整 Key 或签名私钥。
