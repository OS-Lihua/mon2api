# Token2API 号池连接器

Token2API 负责资源挂牌、买家预算、统一 API、用量账本和链上分账。提供者独立运营上游网关，由上游负责账号授权、凭证刷新、调度、额度管理和执行环境。Token2API 使用官方 OpenAI SDK 调用标准文本接口。

## 资源归属

一个连接器只归属一位提供者，可以包含该提供者的多个账号。同一聚合端点若混合不同提供者而不返回归属信息，就无法准确分账。MVP 每个预算会话绑定一个资源、一位提供者和一份价格快照。

## 接入步骤

1. 在提供者自己的环境确认模型可用、账号授权有效。
2. 创建权限仅限模型调用的上游 API Key，不使用管理密钥。
3. 由 Token2API 运营者将网关 origin 加入 `UPSTREAM_ALLOWED_ORIGINS`。远程连接使用 HTTPS。
4. 在“我的资源”创建资源，选择上游网关，填写 `baseUrl`、`apiKey`、准确的模型名和价格。地址可使用任意 API 基础路径，如 `/proxy/openai`；根地址默认使用 `/v1`。不要填写完整的 `/chat/completions`。
5. 用短文本核对最终 usage、上游请求 ID、消费者账单和提供者收入，再测试429、取消和缺失用量。

```dotenv
UPSTREAM_ALLOWED_ORIGINS=https://provider.example.com
SESSION_PASSWORD=<至少32字符的随机秘密>
```

清单按协议、主机和端口精确匹配，不支持域名后缀通配。只有运营者能修改清单。网关不跟随重定向，部署环境应限制访问无关内网和云元数据地址。

上游调用密钥在数据库中密封保存；浏览器和买家平台 Key 不会获得它。平台只接收模型调用 API Key，不接收账号密码或第三方账号授权凭证。更换 `SESSION_PASSWORD` 会使既有登录与密封秘密失效；需要重新登录并重新接入资源。MVP 更换连接器密钥时暂停旧资源并重新挂牌。

## 协议范围

| 项目 | 行为 |
| --- | --- |
| 对外接口 | `/v1/chat/completions`，兼容路径 `/api/v1/chat/completions` |
| 消息 | system、user、assistant，纯文本，序列化总大小最多24KB |
| 上游调用 | 官方 SDK，流式，要求最终 usage |
| 会话 | 服务端按消费者和资源隔离后生成 `x-session-id` |
| 输出限制 | `max_tokens` 范围128至2048 |
| 超时与重试 | 45秒总执行期限；已派发请求不自动重试 |
| 追溯 | 保存上游请求 ID 或 completion ID |
| 暂不支持 | 工具、图片、音频、多协议和任意参数透传 |

上游须支持标准流式 Chat Completions、`stream_options.include_usage` 和字符串消息。其他网关的兼容性需要逐一验证。只获得HTTP响应不能证明账号运行环境隔离有效。

## 计量与异常

完整响应且有有效 usage 时，记录 `upstream_reported` 并按会话价格核销。它表示上游报告的用量，不是独立验证或链上证明。账单哈希仅用于关联记录。

缺 usage、响应截断、已派发后的取消与未知故障进入 `REVIEW`，Token 保持未知并保留预留预算。明确拒绝且未产生成功调用的请求释放预算。429与授权错误返回结构化错误，不重发请求。

运营者依据上游审计记录处理核对，CLI不对外开放：

```bash
pnpm review:resolve <requestId> <inputTokens> <outputTokens> <evidenceReference>
```

必须保留证据引用。核对费用不得超过原预留额，不能将额外成本自动转嫁给消费者。会话有120秒链上退出窗口；网络故障或核对不及时导致无法结算的成本由运营者承担，不能无限冻结链上退款。

## 演示与实际能力

`kind: "demo"` 使用明确标记的模拟响应与演示计量单位，不调用真实模型。`kind: "gateway"` 使用真实上游接口。两者均复用同一账本和资金合约。

账号登录、隔离运行环境、额度冷却和健康检查由提供者的上游系统实现。Token2API 当前没有内置VM编排或账号防封机制，也不承诺账号不会被停用。提供者应验证工具权限、文件系统和网络隔离；Token2API 不发送tools，也不执行返回的工具调用。
