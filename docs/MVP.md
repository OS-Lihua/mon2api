# mon2api MVP

## 产品与技术

提供者挂牌 AI 资源，消费者锁定预算，通过统一 API 调用，平台计量后在 Monad 分账。**一个使用会话固定一个资源、提供者和价格快照**，先跑通闭环，再考虑跨提供者调度。

全栈使用 [T3 Web API Template](https://github.com/PraxisGrove/t3-web-api-template)：Next.js、tRPC、Prisma、PostgreSQL、Zod。REST 与 tRPC 共用领域服务。账号池交给独立上游网关；SSE 使用官方 OpenAI SDK；合约基于 OpenZeppelin，钱包选择和交互用 RainbowKit、wagmi、viem，登录用 iron-session。本地链采用 Ganache。

## 模块职责

| 模块 | MVP 职责 |
| --- | --- |
| 合约 | 锁预算、限制累计消费与 nonce、提供者和平台分账、关闭退款、提现 |
| 后端 | 钱包验签、资源与 Key、价格快照、原子预算预留、用量账本、结算 outbox 与恢复 |
| 前端 | 六页控制台：资源、总览、会话与调用、Key、账单、提供者；完成钱包交易与演示 |
| 号池 | 提供者运营上游网关，负责授权刷新、黏性会话、并发、额度冷却、执行隔离；mon2api 只做连接器 |

合约包含 6 位精度的演示代币 `DemoUSD` 和 `UsageEscrow`。dUSD 可公开铸造，只供测试，不代表可兑付资产。meter 是受信任计量者，按累计消费增量结算；平台默认服务费 5%，手续费按累计金额舍入，不能通过拆批改变费额。

消费者请求关闭或会话自然到期后保留 120 秒结算窗口。meter 可在对账完成后提前关闭；窗口结束后任何人可触发关闭，退款归原消费者。关闭后不能继续扣费。

## 调用与计费

```text
挂牌 → 固定资源和价格 → 链上锁预算 → 创建平台 Key
→ 原子预留 → 上游网关流式调用 → usage 核销 / review
→ outbox → meter 结算 → 提供者提现 → 关闭并退剩余预算
```

对外先支持文本 `/v1/chat/completions`，含流式输出。平台 Key 按会话授权，只保存哈希；上游密钥仅在服务端密封保存。连接器地址必须加入精确 origin 清单，一个连接器只归属一位提供者。

金额均用整数最小单位，1 dUSD = 1,000,000 单位。`inputRate`、`outputRate` 表示每百万 Token 的最小单位价格，例如 `3_000_000` 表示 3 dUSD / 百万 Token。计费使用会话价格快照，按整数规则取整，不用浮点累加。

缺 usage、流式中断或已派发后取消进入 `review`，保留预留额度，不按零用量核销；已派发请求不自动重试。核对必须与合约退出窗口协调，不能无限冻结链上资金。结算 outbox 持久化批次，通过链上 nonce 和事件恢复，防止重启重复分账。

## 验收与边界

两个不同钱包分别扮演提供者和消费者，完成挂牌、锁预算、调用、账单、结算、提现和退款；并发不能超花，重放不能重复扣款，异常用量可见。控制台区分模拟资源、真实连接器、本地链和测试网。

demo 不调用模型，输出及用量明确标为模拟。真实连接器使用 `upstream_reported` 用量，链上账单摘要不能证明模型执行或计量真实。mon2api 未实现 VM 内核或防封机制，部署者需独立验证上游运行环境；接入说明见 [POOL.md](./POOL.md)。

默认在本地 EVM 演示；Monad 测试网需要 RPC、测试 MON 和部署/meter 凭证后实际验证。当前范围不含真实资产、多协议、多模态、跨提供者竞价或去中心化计量证明。实现与外部验证状态见 [TASKS.md](./TASKS.md)。
