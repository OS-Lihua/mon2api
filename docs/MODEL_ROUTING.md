# 模型 Key、统一报价与预付余额

用户创建 API Key，并选择该 Key 允许使用的模型。新增平台模型不会自动授权给已有 Key。Key 不绑定供应商，不复制或分配账户余额。所有模型 Key 共用同一钱包的预付余额；钱包签名登录和模型权限均在服务端校验。

## 模型与路由

管理员用当前托管合约的 owner 钱包配置平台模型 ID、输入/输出统一报价，以及模型对应的真实网关或 pool connector 资源。平台模型 ID 与上游模型 ID 分开保存。较小的路由优先级先被选择；资源必须在线、已上架、有剩余并发，且直连地址已获准。

平台输入和输出报价均不得低于被选择资源的对应报价。修改报价后，超过平台报价的资源不再受理新请求。每次调用在准入时固定供应商、资源、上游模型、用户报价与供应商报价，后续配置变化不修改这份快照。

## 资金与计量

- 账本金额使用结算资产的整数百万分之一；报价使用每百万 Token 的 micro-units。链上金额通过共享工具按 tokenDecimals（6–18）换算。
- 充值和提取由用户钱包逐笔签名。ERC20 充值先将授权置零、再设置本次金额；原生币直接支付充值金额。提取仅使用已确认且未预留的账户余额。
- 推理前先在链上将本次最大费用从预付余额预留为独立租约。输入使用现有文本接口的保守上限，输出使用请求上限；只有预留确认后才调用上游。用户不需要选择或手动创建这些租约。
- 同一 Key 的 Idempotency-Key 跨模型路由保持唯一。已受理的请求不会因为重试而换供应商重发。查询尚在预留阶段的请求返回 409，不把它当成未发生调用的证明。
- 确认用量后，用户费用按平台报价计算。供应商按其报价获得金额，并沿用 5% 平台服务费；平台取得用户费用与供应商净收入的差额。计费统一调用服务端金额服务。
- 不确定用量保持 REVIEW，并保留资金。没有用量时不显示零费用，不自动重发推理。结算完成并关闭内部租约后，未用预留回到统一预付余额；它不转入原会话的可提现余额。
- 预留任务和结算任务先持久化，再准备签名交易；nonce、交易原文和 hash 在广播前保存。恢复流程验证已确认事件，只恢复资金处理，不重复推理。

当前实现每次调用先确认链上预留，因此开始推理前需要等待网络确认；这段时间属于真实准备阶段。结算与退回未用预留由独立 worker 完成。worker 中断时，资金状态继续显示处理中或待核对。

## 部署边界

新预付功能需要包含 prepaidVersion、depositPrepaid、withdrawPrepaid、reservePrepaidSession 和 settlePrepaid 的托管合约。已有不可升级合约不会自动获得这些能力。能力或链连接不可用时，接口返回明确错误，界面不显示虚假的零余额。

已有资源租约、报价、密钥、收入与退款继续按原规则处理。数据库迁移只增加字段和表，不转换原余额，也不将原租约改为预付账户。部署新托管合约时必须使用独立数据库与对应的链/资产/精度配置；先按原市场规则处理旧资金。生产迁移独立于构建，不能由部署构建自动执行。不要将现有数据库重新绑定到另一个托管合约。

## 接口

- GET /api/v1/catalog/models：平台模型与统一报价。
- POST /api/v1/consumer/keys：使用 name 和 models 创建模型 Key。
- POST /api/v1/consumer/keys/{id}/models：调整自己的模型 Key 授权。
- GET /api/v1/consumer/prepaid：读取确认余额与处理中资金。
- POST /api/v1/consumer/prepaid/transactions：构造充值或提取交易，客户端仍须用钱包签名发送。
- GET /v1/models：仅返回该 Key 已授权且平台仍启用的模型。
- POST /v1/chat/completions：按请求模型选择上游，并从统一预付余额计费。

Web 内部通过 tRPC 使用同一服务。外部接口的运行时校验与 OpenAPI 共用 Zod Schema。旧资源预算客户端仍可使用 sessionId 创建对应的单会话 Key。

## 验证

`pnpm verify` 依次运行格式与 lint、TypeScript、测试及生产构建。路由测试覆盖 Key 所有权与模型权限、跨模型幂等、报价和并发筛选、未确认预留，以及不确定执行后不切换上游。合约测试覆盖原生币、6/18 位代币、原会话兼容、资金守恒、退出与精度限制。钱包测试在首个签名前拦截被修改的目标、方法、授权、金额与交易顺序。

本地端到端验证使用独立 schema 与回环 chain 31337：

```bash
pnpm test:native
pnpm test:stable
pnpm test:stable --18-decimals
```

这些命令要求 `DATABASE_URL` 指向专用本地测试库。脚本新建并清理随机 schema，不使用已有业务行或外部签名器；验证模型 Key、平台与上游不同模型 ID、共享预付账户、双报价分账、已上链任务恢复、REVIEW 核对与余额提取。

新增迁移可完整应用。与 Prisma 对比时，现有迁移历史仍有两条 `ConnectorJob` 外键的更新动作差异（SQL 为 NO ACTION，Prisma 默认 CASCADE）；本次新增结构无差异，未改写该历史规则。
